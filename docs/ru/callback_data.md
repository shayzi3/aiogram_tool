### Как это работает?   

Класс `LongCallbackData` наследуется от класса из aiogram `CallbackData`
и переопределяет два метода класса родителя. Первый метод `pack`, его
он переопределяет для того, чтобы отловить ошибку о слишком большом количестве символов.
Если ошибки нет, то возвращается результат родительского метода `pack`, если всё же есть,
то генерируется уникальный идентификатор, который будет ключом, а значением будет
экземпляр созданного вами класса, после этого в атрибут `callback_data` класса `InlineKeyboardButton`
будет сохранён уникальный идентификатор. Что же дальше? А дальше в игру вступает второй
переопределённый метод `filter`, он возвращает экземпляр класса `LongCallbackQueryFilter`.
Теперь подробней про `LongCallbackQueryFilter`. Этот класс является наследником класса
из aiogram `CallbackQueryFilter`. Прежде всего наш класс это фильтр, а значит имеет
магический метод `__call__`. Что же в нём происходит? Проверяется условие на то,
что в `callback_data` содержится ключ идентификатор, если это так, то из memory storage
достаётся экземляр вашей 'длинной' `callback_data` и после чего происходит проверка фильтров.


### Документация

> [!TIP]
> Не нужно в каждый класс наследовать `LongCallbackData`, наследуйте его только тем
> классам, в которых будет превышено количество допустимых символов. Это сделает код понятней.

> [!TIP]
> При перезапуске приложения, кнопки которые содержали в себе сериализованный класс `UniqueIDCallbackData`
> перестанут работать и при нажатии на них появится надпись 'Button expired'.


`class: UniqueIDCallbackData`

     arguments:
          mode: str = "__unique_id_callback"
          unique_id: str

     Этот класс сохраняется сериализованным в атрибут callback_data класса InlineKeyboardButton,
     где изначально в переданном классе было превышение символов. Экземпляр изначального класса
     сохраняется значением в memory storage, где ключом является unique_id.


`class: LongCallbackQueryFilter`

     arguments:
          null

     Данный класс является фильтром. Его основная задача - это проверять
     есть ли в callback_data строка '__unique_id_callback' и если она
     есть, то из memory storage достаётся экземпляр класса, на котором
     уже проверяются указанные фильтры и соответственно именно этот класс
     приходит в аргумент обработчика callback_data.


`class: LongCallbackData`

     arguments:
          null

     Этот класс наследуется от CallbackData. Если у вас
     есть класс, при сериализации которого будет превышено 64
     символа, то вы смело наследуете класс LongCallbackData.
